## 1. Назначение проекта

**Solanace** — self-hosted веб-приложение для каталогизации, просмотра, организации и обработки локального видеоархива, физически расположенного в папках сервера или компьютера, на котором работает приложение.

Система должна решать две группы задач одновременно:

1. **Каталогизация и файловый менеджмент** — показывать реальную файловую структуру, позволять работать с папками и файлами, хранить метаданные и карточки, искать, фильтровать, закреплять и группировать видео.
2. **Медиаобработка** — создавать кадры, миниатюры, аудио, видеофрагменты, MP4-копии, транскрипты, переводы и результаты склейки, не разрушая исходный видеоархив.

Solanace не является медиасервером типа Plex/Jellyfin и не должен перестраивать архив в собственное хранилище. **Исходные видео остаются там, где их положил пользователь.** База данных и служебный кэш являются надстройкой над существующей файловой системой.

Основная модель использования — один администратор или ограниченный круг доверенных пользователей во внутренней сети, за VPN либо reverse proxy.

## 2. Ключевые принципы

### 2.1. Файловая система — источник истины для исходных видео

Исходный видеофайл не копируется в базу и не перемещается в отдельное хранилище автоматически. Его физический путь определяется выбранным корнем библиотеки и относительным путем.

### 2.2. БД хранит индекс, метаданные и связи

MySQL/MariaDB хранит:

- список подключенных библиотек;
- кэш папок и видеофайлов;
- карточки;
- категории;
- привязки категорий;
- закрепления;
- сведения о кадрах и выбранной миниатюре;
- производные файлы;
- транскрипты и их сегменты;
- переводы;
- фоновые задания;
- provenance склеек и видеофрагментов.

### 2.3. Служебные медиафайлы хранятся рядом с библиотекой

Для каждой библиотеки создается служебный каталог:

```text
<library root>/.video_catalog_screenshots/
```

В нем хранятся автоматически созданные кадры, уменьшенные миниатюры, аудио, видеофрагменты, конвертированные MP4 и другие производные файлы.

### 2.4. Карточка должна переживать переименование и перемещение видео

Карточка идентифицируется не только по пути, а по стабильному `file_hash`.

Алгоритм быстрого хэша должен быть одинаковым во всех компонентах приложения:

1. SHA-1 context;
2. строка `video-file-v2|<размер файла>|`;
3. первый 1 MiB файла;
4. если файл больше 1 MiB — последний 1 MiB.

Этот хэш не является криптографической гарантией подлинности; он служит быстрым контентным fingerprint для сопоставления видео.

### 2.5. Кроссплатформенность

Одна кодовая база должна работать на:

- Windows 10/11, в том числе Laragon;
- Linux, в том числе Debian/Ubuntu-подобных системах.

Нельзя жестко зашивать разделитель каталогов, буквы дисков или единственный путь к PHP/FFmpeg/Python. Внутренняя логика должна корректно нормализовать `\` и `/`.

## 3. Технологический стек

Минимально допустимая архитектура:

- Backend: PHP 8.1+;
- DB: MySQL 8+ или актуальная MariaDB;
- Frontend: HTML/CSS/Vanilla JavaScript;
- Web server: Apache или Nginx;
- Media processing: FFmpeg + ffprobe;
- Transcription/translation bridge: Python для текущего Groq SDK;
- Authentication: PHP sessions + Argon2id;
- Background workers: detached PHP CLI processes, вызывающие FFmpeg/Python.

Не требуется Node.js, npm, frontend build pipeline или Docker.

---

## 4. Термины

**Инстанс** — отдельная установка Solanace со своей БД и `uploads/`.

**Библиотека** — выбранная пользователем корневая серверная папка с видео.

**Корень библиотеки** — абсолютный путь, например `D:\Video` или `/srv/media`.

**Кэш библиотеки** — записи `library_files` и `library_dirs`, позволяющие отображать дерево без полного сканирования диска при каждом открытии.

**Карточка** — пользовательские метаданные, связанные с видео через `file_hash`.

**Производный файл** — аудио, видеофрагмент, TXT, конвертированный MP4 и т. п., созданные Solanace.

**Продвинутый фрагмент** — видеофрагмент, который пользователь сделал обычным самостоятельным видео библиотеки.

**Транскрипт** — полный распознанный текст с временными сегментами.

**Перевод** — машинный либо пользовательский вариант текста транскрипта.

# ЧАСТЬ I. ИНТЕРФЕЙС

## 5. Общий стиль

### 5.1. Визуальная концепция

Интерфейс должен быть минималистичным, светлым и спокойным, но не выглядеть как набор белых прямоугольников на белом фоне.

Базовые признаки:

- светлый серо-фиолетовый фон;
- мягкие градиенты;
- белые/слегка тонированные панели;
- тонкие серо-фиолетовые границы;
- умеренные тени;
- основной акцент — фиолетовый цвет из логотипа Solanace;
- скругления около 10–16 px;
- без тяжелой анимации;
- интерфейс ориентирован на desktop и широкоформатные мониторы.

### 5.2. Брендинг

Использовать логотип `assets/solanace-logo.png`.

В главном окне логотип заменяет старый текстовый заголовок типа «Локальный видеокаталог».

На странице входа тот же логотип является основным визуальным идентификатором.

### 5.3. Языки

Весь пользовательский интерфейс должен поддерживать:

- русский;
- английский.

Переключатель `RU / EN` присутствует:

- на странице входа;
- на главной странице.

Выбор сохраняется в `localStorage`. Серверные сообщения авторизации должны по возможности учитывать выбранный язык.

Пользовательский контент — имена файлов, заметки, заголовки, транскрипты — не переводится автоматически.

## 6. Страница авторизации

### 6.1. Состав

Страница должна содержать:

- логотип Solanace;
- переключатель RU/EN;
- поле логина;
- поле пароля;
- slider CAPTCHA;
- кнопку входа.

### 6.2. Slider CAPTCHA

Текст: «Протяните ползунок вправо» / `Drag the slider to the right`.

Кнопка входа должна быть заблокирована, пока ползунок не доведен до конца.

После успешного протягивания отображается состояние «Готово» / `Done`.

Проверка должна быть привязана к текущей PHP-сессии/nonce. Это дополнительный локальный anti-bot барьер, но не замена внешней CAPTCHA.

### 6.3. Авторизация

В системе один локальный аккаунт.

Стандартные данные после чистой установки:

```text
admin / admin
```

Пароль хранится через Argon2id. Legacy MD5 допускается только для миграции старой установки; после успешного входа старый MD5 должен быть автоматически заменен на Argon2id.

## 7. Главный экран

### 7.1. Общая ширина

Основной контейнер рассчитан примерно на `max-width: 1620px` и центрируется. На узких экранах должен переходить к одноколоночной адаптивной раскладке.

### 7.2. Предупреждение о стандартных паролях

В самом верху страницы показывается предупреждающая плашка, если:

- пароль приложения по-прежнему `admin`;
- и/или в `config.php` используется `DB_USER=admin`, `DB_PASS=admin`.

Плашка должна явно объяснять, что необходимо изменить.

### 7.3. Верхняя шапка

Слева — логотип.

Справа:

- RU/EN;
- кнопка **«Действия»**;
- выпадающее меню действий.

### 7.4. Панель выбора библиотеки

Содержит:

- поле **«Папка с видео»**;
- кнопку **«Показать файлы»**;
- **«Обновить кэш»**;
- **«Удалить кэш»**;
- **«В избранное»**.

Поле принимает Windows и Linux пути.

Под кнопками показываются:

- дата/время последнего обновления кэша;
- статус фонового создания кадров;
- кнопки остановки/продолжения worker при необходимости.

Ниже — список закрепленных/избранных корневых папок. Клик открывает соответствующую библиотеку; можно удалить папку из списка избранного, не удаляя библиотеку и файлы.

### 7.5. Поиск и категории

Отдельная компактная панель по центру страницы:

- поле поиска шириной примерно до 420 px;
- список категорий примерно до 280 px;
- кнопка сброса.

Эти элементы **не должны растягиваться на всю ширину widescreen экрана**.

Поиск выполняется по:

- имени файла;
- пользовательскому заголовку;
- заметке;
- пути;
- категории;
- тексту транскрипта.

Результаты показываются отдельным блоком и поддерживают те же массовые действия над файлами.

### 7.6. Закрепленные видео

Если в текущей библиотеке есть закрепленные видео, перед основной файловой областью отображается раскрываемая секция **«Закрепленные видео»**.

Вид секции соответствует текущему глобальному режиму:

- список;
- миниатюры.

Закрепленное видео также остается на своем обычном месте в папке.

## 8. Основная файловая область

### 8.1. Общая компоновка

Рабочая область на desktop делится на две части:

- слева — дерево папок, около 310 px;
- справа — содержимое выбранной папки, все оставшееся пространство.

При ширине около 1180 px и ниже раскладка может переходить в одну колонку.

### 8.2. Левая панель — дерево папок

Вверху:

- заголовок «Папки»;
- счетчик папок;
- небольшая строка **«Поиск по папкам…»**.

Дерево должно показывать **только каталоги**, без файлов внутри дерева.

Ветки раскрываются/сворачиваются стрелками.

Клик по названию папки:

- делает ее текущей;
- показывает ее файлы справа.

Правый клик открывает контекстное меню доступных файловых действий.

### 8.3. Высота дерева

Дерево не должно иметь отдельного постоянного вертикального scrollbar на desktop. Панель увеличивается вниз по мере раскрытия ветвей вместе с высотой страницы.

### 8.4. Поиск по папкам

Фильтр выполняется локально по уже загруженному дереву.

При вводе:

- показываются папки, имя которых содержит запрос;
- сохраняются все родительские папки, необходимые для отображения пути к совпадению;
- соответствующие ветви временно раскрываются.

После очистки поиска возвращается сохраненное пользовательское состояние раскрытия дерева.

### 8.5. Правая панель — текущая папка

Вверху показываются:

- название текущей папки;
- breadcrumb путь;
- количество файлов и подпапок.

### 8.6. Breadcrumbs

Путь должен быть разбит на кликабельные части, например:

```text
media › Films › Documentary › Nature
```

Клик по `Films` немедленно открывает эту папку справа и синхронизирует активный пункт дерева.

### 8.7. Подпапки текущей папки

При наличии подпапок справа над файлами могут выводиться компактные кнопки/chips. Клик открывает подпапку.

### 8.8. Режимы отображения

Глобальный переключатель:

- **Список**;
- **Миниатюры**.

Выбор сохраняется в `localStorage`.

#### Список

Строка файла должна содержать:

- checkbox;
- название;
- категорию при наличии;
- длительность;
- кнопку просмотра;
- значок закрепления.

Название открывает карточку.

#### Миниатюры

Плитка должна содержать:

- checkbox;
- назначенную либо стандартную миниатюру;
- название;
- длительность;
- кнопку просмотра;
- значок закрепления;
- категорию при наличии.

Клик по миниатюре/названию открывает карточку.

Миниатюры должны подгружаться лениво.

### 8.9. Сортировка

Четыре режима:

1. По алфавиту А–Я.
2. По алфавиту Я–А.
3. По длительности по возрастанию.
4. По длительности по убыванию.

Сортировка применяется к файлам выбранной папки и влияет также на порядок перелистывания карточек.

Выбор сохраняется в `localStorage`.

## 9. Выделение и массовые операции

Каждый файл и папка имеют checkbox.

При выборе хотя бы одного объекта показывается sticky/контекстная панель:

- количество выбранных;
- **Переместить…**;
- **В категорию…** — только если выбраны исключительно видео;
- **Склеить** — если выбрано минимум два видео;
- **Удалить с диска**;
- **Снять выделение**.

Выделение работает также в результатах поиска и в секции закрепленных видео.

Drag-and-drop использует текущее выделение: если перетаскиваемый объект не был выбран, выделение переключается на него.

## 10. Контекстное меню файловой структуры

Правый клик должен давать операции, соответствующие типу объекта:

Для папки:

- создать подпапку;
- переместить;
- удалить;
- иные применимые операции.

Для корня:

- создать папку первого уровня.

Для файла:

- открыть карточку;
- просмотр;
- перемещение;
- удаление и другие поддерживаемые действия.

Все физические операции обязаны одновременно синхронизировать кэш БД.

# ЧАСТЬ II. КАРТОЧКА ВИДЕО

## 11. Общая компоновка карточки

Карточка — модальное окно с ограниченной шириной примерно:

```css
width: min(1380px, 94vw);
max-height: 92vh;
```

Она не должна растягиваться до 100% экрана.

Колонки на широком экране:

```text
1/4 | 2/4 | 1/4
```

На средних экранах правая колонка переносится вниз, на мобильных все становится одной колонкой.

### 11.1. Верхняя строка

Слева — имя реального файла.

Рядом — навигация карточек:

```text
‹   3 / 12   ›
```

Стрелки перелистывают только видео текущей папки в текущем порядке сортировки.

На первом/последнем элементе соответствующая стрелка disabled.

Горячие клавиши:

- `Alt + ←` — предыдущая;
- `Alt + →` — следующая.

Путь к файлу отображается под именем.

---

## 12. Левая колонка карточки

### 12.1. Основная миниатюра

В верхней части — назначенная миниатюра.

Если пользователь не выбирал кадр, используется стандартный автоматический кадр.

Если кадры отсутствуют, показывается placeholder.

Поверх миниатюры допускается значок Play.

**Клик по миниатюре запускает встроенный просмотр видео.**

### 12.2. Факты о файле

Под миниатюрой:

- размер;
- длительность;
- дата добавления в библиотеку.

### 12.3. Главная кнопка медиаинструмента

Кнопка:

**«Вырезка/Аудио/Транскрипт»**.

Если текущий контейнер/кодек неудобен для браузера, отдельно показывается **«Конвертировать в mp4»**.

### 12.4. Производные данные

Ниже отдельными блоками без лишних спойлеров идут:

1. **Видеофрагменты**.
2. **Аудио**.
3. **Транскрипты**.
4. **Созданные из фрагментов видео** — при наличии.
5. **Исходное видео для этого фрагмента** — если текущий файл сам был создан из фрагмента.

#### Видеофрагмент

Название кликабельно и запускает просмотр фрагмента.

Справа маленькая шестеренка. Меню:

- Скачать;
- Сделать обычным видео;
- Удалить.

#### Аудио

Должен быть компактный встроенный audio player либо понятный способ прослушивания.

Шестеренка:

- Удалить.

Скачивание аудио допустимо кликом по имени/ссылке.

#### Транскрипт

Название открывает окно просмотра транскрипта.

Шестеренка:

- Скачать TXT;
- Перевести;
- Удалить.

## 13. Центральная колонка карточки

### 13.1. Первая строка

В одну строку:

- **Кастомный заголовок**;
- **Категория**.

На узких экранах поля могут располагаться вертикально.

### 13.2. Заметки

Большое textarea под основной строкой.

Заметка сохраняется в карточке и участвует в поиске.

### 13.3. Кадры

Ниже — блок **«Кадры из видео»**.

Все автоматически созданные кадры показываются непосредственно, **без `<details>`/спойлера**.

Обычно 10 кадров.

Клик открывает полноразмерный просмотр кадров.

В просмотрщике:

- предыдущий/следующий;
- клавиатура/мышь;
- wheel/navigation;
- кнопка-звезда «Сделать миниатюрой».

Выбранный кадр сохраняется в `thumbnail_sort_order`.

### 13.4. Прикрепленные фото

Ниже кадров:

- существующие прикрепленные изображения;
- кнопка удаления каждого;
- input выбора нескольких изображений;
- кнопка загрузки.

Файлы физически хранятся в `uploads/` инстанса, но отдаются браузеру только через авторизованный endpoint.

Ниже — создание новой категории:

- поле названия;
- кнопка **Добавить**.

Ниже, при наличии, блок **«Склейка из видео»** со списком исходных видео в порядке их объединения. Ссылки на существующие источники должны открывать карточки этих файлов.

## 15. Нижняя панель карточки

На одной линии:

Слева:

- **Удалить карточку**.

Справа:

- статус сохранения;
- **Сохранить**;
- **Удалить с диска**.

**Удалить карточку** удаляет только пользовательские метаданные/изображения карточки, не исходное видео.

**Удалить с диска** удаляет исходный видеофайл, запись кэша, карточку, связанные производные файлы и служебные связи. Требуется явное подтверждение.

# ЧАСТЬ III. МЕДИАОБРАБОТКА

## 16. Окно «Вырезка / Аудио / Транскрипт»

### 16.1. Общий интервал

Вверху два поля:

- От;
- До.

Принимается формат времени, понятный приложению, например `HH:MM:SS`.

### 16.2. Опции

Три независимых checkbox-блока:

1. **Вырезать фрагмент видео**.
2. **Получить аудио**.
3. **Транскрипт**.

### 16.3. Логика комбинаций

- clip — создается только видеофрагмент;
- audio — только аудио;
- transcript — создается аудио + транскрипт;
- clip + audio — оба результата;
- clip + transcript — клип + аудио + транскрипт;
- audio + transcript — аудио создается один раз;
- все — клип + одно аудио + транскрипт.

### 16.4. Аудио

Форматы:

- MP3;
- FLAC.

MP3 bitrate:

- 64;
- 96;
- 192 kbps.

### 16.5. Транскрипция

Язык:

- auto;
- ru;
- en.

Пустые границы для аудио/транскрипта означают весь файл. Для вырезки должна быть задана хотя бы одна осмысленная граница.

### 16.6. Фоновые задания

Длительные операции запускаются worker'ом и не должны блокировать HTTP-request до завершения FFmpeg/Python.

В БД хранится status/message/started/finished и связь с производным файлом.

---

## 17. Конвертация в MP4

Для форматов, которые браузер обычно не воспроизводит напрямую, карточка предлагает конвертацию.

Целевой формат:

- video: H.264;
- audio: AAC;
- container: MP4.

Конвертированный файл хранится как derivative и используется для веб-просмотра.

После успешной конвертации допускается действие **«Удалить исходное»**, которое заменяет исходный файл конвертированным MP4, корректно пересчитывает fingerprint и обновляет БД/карточку/кадры.

---

## 18. Продвижение видеофрагмента

Действие **«Сделать обычным видео»** должно:

1. физически переместить фрагмент из служебного каталога в корень/рабочую часть библиотеки;
2. создать обычную запись `library_files`;
3. поставить 10 кадров на генерацию;
4. сохранить provenance source → promoted;
5. перенести совпадающие по интервалу аудио и транскрипт;
6. перенести переводы;
7. пересчитать таймкоды относительно начала фрагмента.

Пример:

Исходный сегмент был на `01:20:07`. Если promoted clip начинается с `01:20:00`, новый таймкод должен стать `00:00:07`.

Карточка исходного видео показывает ссылку на созданный файл; карточка созданного — ссылку на исходник.

# ЧАСТЬ IV. ТРАНСКРИПЦИЯ И ПЕРЕВОД

## 19. Настройки транскрибации

В **Действия → Настройки → Транскрибация**:

- provider;
- model;
- API key;
- Python executable.

Архитектура provider → model должна позволять добавлять провайдеры без переписывания основного UI.

Текущий provider: `groq`.

Текущие модели:

- `whisper-large-v3`;
- `whisper-large-v3-turbo`.

Python bridge должен называться так, чтобы не shadow'ить установленный пакет `groq`; локальный файл `groq.py` использовать нельзя.

---

## 20. Хранение транскрипта

Для каждого транскрипта сохраняются:

- исходный `library_file_id`;
- source hash;
- аудиопроизводная;
- TXT derivative;
- provider/model/language;
- общий interval;
- полный текст;
- сегменты с `start_seconds`, `end_seconds`, `sort_order`, `segment_text`.

Для больших файлов provider bridge должен уметь делить аудио на части, а после распознавания корректно сдвигать таймкоды и объединять результаты.

---

## 21. Окно просмотра транскрипта

Широкая модалка.

Вверху:

- название/метаданные;
- селектор версии текста;
- **Скачать TXT**;
- **Перевести**;
- **Добавить фрагмент**.

Ниже список сегментов:

```text
[00:00:12] Текст сегмента...
```

Таймкод кликабелен и открывает видео с соответствующей позиции.

У каждого сегмента при наведении:

- edit;
- delete.

Редактирование сохраняется без полного reload страницы.

Добавление нового сегмента принимает строку вида:

```text
[00:12:35] Новый текст
```

После добавления сегменты сортируются по времени.

---

## 22. Переводы транскриптов

### 22.1. Настройки

В **Действия → Настройки → Перевод**:

- provider;
- model;
- API key;
- Python executable.

Если Groq API key/Python для перевода пусты, допускается fallback на настройки транскрибации.

### 22.2. Машинный перевод

Целевые языки минимум:

- ru;
- en.

Если язык оригинала совпадает с целевым, лишний API-вызов делать не нужно.

Текущие модели:

- `openai/gpt-oss-20b`;
- `openai/gpt-oss-120b`.

### 22.3. Надежность пакетного перевода

Сегменты должны переводиться пакетами, но границы одного сегмента нельзя разрывать.

Для привязки ответа к исходным сегментам использовать устойчивый marker protocol с ID сегмента, а не зависеть от строгого Structured Outputs API.

При malformed response пакет делится и повторяется.

При API limit / payload error пакет уменьшается по границам сегментов.

Для rate limit выполняются ограниченные backoff retries.

### 22.4. Пользовательский перевод

Окно перевода также позволяет импортировать TXT.

Поддерживаемый формат:

```text
[00:00:12] Первая строка
продолжение первого сегмента
[00:00:35] Второй сегмент
```

Поддерживаются `[MM:SS]`, `[HH:MM:SS]` и миллисекунды.

Пользователь задает название, например `Перевод Иванова`.

Пользовательский перевод может иметь собственную сегментацию, не совпадающую с оригиналом.

### 22.5. Версии

В viewer dropdown отображаются:

- оригинал;
- машинные переводы;
- пользовательские варианты.

Выбранный вариант сохраняется в `localStorage` для конкретного транскрипта.

Каждый перевод можно удалить отдельно.

# ЧАСТЬ V. СКЛЕЙКА ВИДЕО

## 23. Диалог склейки

Доступен при выделении минимум двух видео.

Содержит:

- список источников;
- drag-and-drop reordering;
- обязательное имя результата;
- разрешение:
  - Auto;
  - 1920×1080;
  - 1280×720;
- обработка пропорций:
  - fit/pad;
  - fill/crop;
- качество;
- режим:
  - авто — без перекодирования, если возможно;
  - всегда перекодировать.

### 23.1. Быстрая склейка

Если источники совместимы по существенным параметрам H.264/AAC, использовать concat без перекодирования.

### 23.2. Нормализованная склейка

Если параметры различаются:

- привести video к целевому разрешению/геометрии;
- H.264;
- audio AAC;
- если в клипе нет аудио — добавить тишину;
- затем объединить.

### 23.3. Фоновый прогресс

Worker должен обновлять:

- процент;
- stage;
- processed seconds;
- total seconds;
- heartbeat.

На Windows не следует полагаться на долгоживущие `proc_open` pipes для чтения FFmpeg progress; рабочий вариант — `-progress` в temp file с периодическим polling.

### 23.4. Результат

После завершения:

- файл появляется в библиотеке;
- запись кэша создается сразу;
- 10 кадров ставятся в очередь;
- создается `video_merges`;
- порядок источников сохраняется в `video_merge_sources`.

При последующем перемещении/переименовании источника ссылка должна сохраняться по `library_file_id`. Историческая информация о source hash/name/path должна оставаться доступной для provenance.

# ЧАСТЬ VI. КЭШ И ФАЙЛОВАЯ СИСТЕМА

## 24. Первичное подключение корня

При выборе неизвестного корня:

1. проверить разрешенность пути;
2. создать `library_roots`;
3. создать UUID `library_uid`;
4. записать `<root>/.video_catalog_screenshots/library.id`;
5. рекурсивно просканировать директории и поддерживаемые видео;
6. заполнить `library_dirs` и `library_files`;
7. создать pending screenshot sets;
8. запустить/поставить в очередь создание кадров.

После этого обычное открытие библиотеки строит дерево из БД.

---

## 25. Обновление кэша

Кнопка **«Обновить кэш»** выполняет реальное сравнение диска с кэшем.

Должны определяться:

- новые файлы;
- удаленные;
- измененные;
- перемещенные/переименованные;
- новые/удаленные папки;
- пустые папки.

Для файлов обновляются size, mtime, path и hash при необходимости.

Если найден прежний `file_hash` по другому пути, карточка должна остаться привязанной.

---

## 26. Идентичность библиотеки при смене пути

`library_uid` записывается в `library.id` внутри служебной папки корня.

Если пользователь перенес всю библиотеку либо поменял букву диска и затем выбирает новый путь, Solanace должен обнаружить тот же UID и выполнить relocation записей БД, сохранив карточки, категории и производные связи.

---

## 27. Удаление кэша

Кнопка **«Удалить кэш»** относится к текущей библиотеке и должна удалять:

- `library_files` / `library_dirs` кэш;
- per-library category mappings и категории;
- screenshot DB records;
- производные аудио/фрагменты/converted;
- транскрипты и переводы;
- worker/job state;
- `.video_catalog_screenshots`.

**Исходные видео удалять нельзя.**

Карточки/ручные изображения, связанные по hash и потенциально пригодные при повторном подключении, должны обрабатываться консервативно согласно текущей логике проекта.

# ЧАСТЬ VII. КАТЕГОРИИ, ПОИСК, МЕТАДАННЫЕ

## 28. Категории

Категории имеют namespace конкретной библиотеки (`root_id`). Одинаковое имя категории может существовать в разных библиотеках независимо.

Назначение категории хранится через `library_file_categories`, а не глобально в карточке, чтобы один и тот же hash мог иметь разные категории в разных корнях.

Категорию можно:

- создать в карточке;
- выбрать в карточке;
- назначить группово;
- импортировать из таблицы;
- использовать как фильтр.

---

## 29. Поиск

Поиск выполняется по текущей библиотеке и включает:

- `file_name`;
- путь;
- `custom_title`;
- `note`;
- category name;
- transcript full text.

Результаты должны содержать checkbox и поддерживать group move/delete/category/merge.

---

## 30. Групповой импорт метаданных

Поддержать XLSX/CSV.

Минимальные логические поля:

- имя файла / относительный путь;
- custom title;
- note;
- category.

Если в разных подпапках есть одинаковые имена, пользователь может указывать относительный путь.

Неизвестная категория создается автоматически в текущей библиотеке.

---

## 31. Групповой просмотр

### 31.1. Метаданные

Табличное окно по текущей библиотеке с поиском и открытием карточки.

### 31.2. Кадры

Строка на видео, первые пять автоматических кадров, возможность открыть полноразмерный gallery viewer в пределах текущей строки и перейти в карточку.

# ЧАСТЬ VIII. ЭКСПОРТ И ИМПОРТ

## 32. Экспорт библиотеки

Пункт: **Действия → Экспорт библиотеки**.

Экспорт относится только к текущей библиотеке.

ZIP создается в ее корне:

```text
solanace_export_YYYY-MM-DD_HH-MM-SS.zip
```

### 32.1. Формат

ZIP обязан содержать manifest, например:

```json
{
  "format": "solanace-library-export",
  "version": 1
}
```

и сериализованные данные библиотеки.

### 32.2. Что включать

- список файлов с relative path, hash, size, mtime, pin;
- директории;
- категории;
- назначения категорий;
- карточки;
- attachments;
- screenshot sets и кадры;
- derivatives;
- transcripts/segments;
- translations/segments;
- merge provenance;
- promoted clip relations;
- служебные файлы `.video_catalog_screenshots`.

### 32.3. Что исключать

- исходные видео;
- app_auth;
- пароль БД;
- API keys;
- transcription/translation provider settings;
- текущие внутренние ID как обязательную идентичность нового инстанса.

Legacy ID можно хранить только как временные reference keys внутри архива.

## 33. Импорт библиотеки

Пункт: **Действия → Импорт библиотеки**.

Импорт выполняется в выбранный текущий root нового инстанса.

Пользователь может:

- выбрать ZIP, уже лежащий в корне сервера;
- загрузить ZIP через браузер.

Для больших архивов предпочтительнее server-side выбор из корня, чтобы не зависеть от `upload_max_filesize` и reverse proxy limits.

### 33.1. Подпапка перенесенных файлов

Опциональное поле:

**«Подпапка с перенесенными файлами»**.

Пусть в экспорте было:

```text
Films/Movie.mkv
```

а на новом сервере:

```text
<new root>/Archive2026/Films/Movie.mkv
```

Тогда пользователь вводит:

```text
Archive2026
```

Итоговый target relative path:

```text
Archive2026/Films/Movie.mkv
```

Поле не должно допускать `..`, absolute path, drive prefix или выход из выбранного root.

### 33.2. Сопоставление

Старые абсолютные пути игнорируются.

Файл должен сопоставляться по:

1. ожидаемому target relative path;
2. `file_hash`;
3. при необходимости дополнительным проверкам size/mtime как диагностике, но hash является главным контентным fingerprint.

Если файл отсутствует или hash другой, импорт не должен присоединять к нему чужие метаданные.

### 33.3. Новые ID

Все ID целевого инстанса создаются/сопоставляются заново:

- `root_id`;
- `library_file_id`;
- category IDs;
- card IDs;
- derivative IDs;
- transcript IDs;
- translation IDs;
- merge IDs.

Нельзя вставлять старые primary keys как идентичность новой БД.

### 33.4. Файловая структура

Импорт не должен:

- перемещать исходные видео;
- переименовывать их;
- изменять каталогизацию пользователя.

Он только восстанавливает кэш/метаданные и копирует служебный кэш в правильное место.

### 33.5. Итоговый отчет

После импорта показать минимум:

- сколько файлов сопоставлено;
- сколько не сопоставлено;
- сколько карточек восстановлено;
- категории;
- derivatives;
- transcripts/translations;
- attachments;
- предупреждения/ошибки.

# ЧАСТЬ X. БЕЗОПАСНОСТЬ

## 35. Модель угроз

Приложение не проектируется как публичный multi-tenant SaaS. Однако неавторизованный пользователь не должен получить:

- содержимое БД;
- произвольный доступ к файловой системе;
- прямой доступ к исходным видео через подстановку пути;
- attachments;
- возможность выполнять изменяющие запросы без CSRF;
- доступ к worker/lib/config файлам через HTTP.

---

## 36. Обязательные меры

### 36.1. Сессии

- `session.use_strict_mode=1`;
- HttpOnly;
- SameSite=Lax;
- Secure при HTTPS;
- regeneration после login.

### 36.2. CSRF

Все state-changing запросы требуют CSRF token. API-клиент отправляет его в заголовке `X-CSRF-Token`.

### 36.3. SQL

Все пользовательские значения — prepared statements.

### 36.4. Файловые пути

Любая операция должна проверять, что target находится внутри разрешенного корня.

Опциональный hard boundary:

```php
define('ALLOWED_MEDIA_ROOTS', [...]);
```

Пустой массив — разрешены все пути, доступные PHP-пользователю после авторизации.

### 36.5. media.php

Нельзя принимать произвольный base64 absolute path и читать его.

Видео должно выдаваться только если оно найдено в `library_files` либо является разрешенным derivative текущего файла.

Поддержать HTTP Range для `<video>`.

### 36.6. image.php

Attachments выдаются только после проверки session и существования записи БД.

Прямой доступ к `/uploads/...` блокируется.

### 36.7. HTTP headers

Минимум:

- CSP;
- X-Frame-Options: DENY;
- X-Content-Type-Options: nosniff;
- Referrer-Policy;
- Permissions-Policy.

### 36.8. Worker endpoints

Файлы `*_worker.php` не должны быть обычными HTTP endpoints. Разрешен CLI запуск.

### 36.9. Uploads

Ограничивать:

- допустимые image MIME/type;
- количество файлов;
- размер одного файла, по умолчанию 20 MiB;
- случайное серверное имя.

### 36.10. Export/import ZIP

Не допускать Zip Slip:

- запрет `../`;
- запрет absolute path;
- запрет Windows drive prefix;
- нормализация separator;
- extraction только в заранее известные service destinations.

---

## 37. Reverse proxy

По умолчанию `X-Forwarded-*` не доверяются.

`TRUST_PROXY_HEADERS=true` допустим только если backend недоступен напрямую из недоверенной сети и proxy гарантированно перезаписывает `X-Forwarded-Proto`.

# ЧАСТЬ XII. КРОССПЛАТФОРМЕННОСТЬ

## 40. Пути

Поддержать:

```text
D:\Video\Films\movie.mkv
```

и:

```text
/srv/media/Films/movie.mkv
```

Для сравнений использовать нормализованную форму. Для фактических файловых операций использовать корректный separator текущей ОС.

Relative paths внутри JSON/export должны храниться с `/`, чтобы архив был переносимым между ОС.

---

## 41. Поиск FFmpeg/PHP/Python

`FFMPEG_PATH`, `FFPROBE_PATH`, `PHP_CLI_PATH` могут быть пустыми.

При пустом значении искать:

- PATH;
- `PHP_BINDIR` для PHP CLI;
- типовые Laragon/Windows locations;
- `tools/ffmpeg/bin` проекта;
- системные Linux paths.

Python для Groq задается в Settings и может быть абсолютным путем.

# ЧАСТЬ XIII. НАДЕЖНОСТЬ И UX

## 42. Долгие операции

Нельзя удерживать браузерный HTTP-request в ожидании многоминутного FFmpeg.

Схема:

1. endpoint создает job;
2. запускает CLI worker detached;
3. UI polling получает status;
4. worker периодически обновляет heartbeat/progress;
5. по завершении UI обновляет карточку/дерево.

---

## 43. Ошибки

Пользователь должен получать понятное сообщение, а не raw PHP warning/stack trace.

JSON endpoint всегда возвращает валидный JSON.

Текстовые downloads не должны содержать PHP warnings до содержимого файла.

FFmpeg stderr сохраняется/преобразуется в диагностическое сообщение job.

---

## 44. Сохранение состояния UI

В `localStorage` разрешается хранить:

- язык;
- текущий root;
- favorite roots;
- раскрытые папки;
- list/tile mode;
- sort mode;
- текущую выбранную папку;
- выбранный translation variant.

Секреты в localStorage не хранить.

---

# ЧАСТЬ XIV. РАЗВЕРТЫВАНИЕ

## 45. Конфигурация БД по умолчанию

Чистый пакет:

```php
DB_HOST = 127.0.0.1
DB_NAME = solanace
DB_USER = admin
DB_PASS = admin
```

`database_bootstrap.sql` создает базу и DB account с правами только на `solanace`.

`install.sql` создает полную схему.

---

## 46. Права файловой системы

PHP user должен иметь:

- read корня библиотеки для просмотра;
- write для перемещения/удаления/создания `.video_catalog_screenshots`/экспорта;
- write на `uploads/`.

Не рекомендуется запускать веб-сервер от root/Administrator, если это не требуется системой.

---

## 47. Apache

Repository должен содержать `.htaccess`, запрещающий:

- directory listing;
- прямой web access к config/lib/worker/sql/python;
- direct `/uploads/`.

`.video_catalog_screenshots` также получает свой защитный `.htaccess`.

---

## 48. Nginx

Поскольку `.htaccess` не работает, README должен содержать пример deny rules для service files и uploads.

# ЧАСТЬ XV. КРИТЕРИИ ПРИЕМКИ

## 49. Базовая библиотека

Сценарий считается пройденным, если:

1. пользователь вводит новый root;
2. Solanace индексирует видео и папки;
3. дерево слева отображает только папки;
4. справа показываются только файлы выбранной папки;
5. breadcrumbs работают;
6. list/tile и четыре сортировки работают;
7. повторное открытие не вызывает обязательного полного rescanning;
8. refresh cache обнаруживает изменения диска.

---

## 50. Перемещение

1. Создать карточку видео.
2. Переименовать/переместить файл через Solanace или на диске.
3. Обновить кэш.
4. Карточка, заметка и связанные данные должны остаться у этого видео.

---

## 51. Кадры

1. Новое видео получает pending screenshot set.
2. Worker создает 10 файлов.
3. Карточка показывает 10 кадров.
4. Плиточный режим показывает миниатюру.
5. Пользователь назначает другой кадр.
6. Он становится основной миниатюрой после повторного открытия.

---

## 52. Карточка

1. Открывается widescreen modal 1/4–2/4–1/4.
2. Миниатюра запускает видео.
3. Заголовок/категория/заметка сохраняются.
4. Фото загружается и открывается.
5. Pin отражается и на главном экране.
6. `‹/›` перелистывают только текущую папку с учетом sort order.

---

## 53. Аудио/клип/транскрипт

Проверить все основные комбинации checkbox. Не должно появляться duplicate audio при одновременном audio+transcript.

Фрагмент должен просматриваться, скачиваться, удаляться и продвигаться в обычное видео.

---

## 54. Транскрипт и перевод

1. Создать transcript.
2. Открыть по клику на названии.
3. Таймкоды запускают video seek.
4. Edit/delete/add segment работают без full reload.
5. Machine translation создается.
6. Manual TXT import создается.
7. Viewer переключает версии.
8. Download TXT корректен в UTF-8.
9. Transcript text находится глобальным поиском.

---

## 55. Склейка

1. Выбрать ≥2 файлов.
2. Поменять порядок.
3. Запустить merge.
4. UI показывает прогресс.
5. Result появляется в библиотеке.
6. Его карточка показывает ordered source provenance.

---

## 56. Экспорт/импорт

### Вариант A — тот же relative root

1. Экспортировать библиотеку.
2. Скопировать исходные видео и ZIP на новый инстанс.
3. Импортировать без subfolder prefix.
4. Метаданные и кэш восстановлены.

### Вариант B — дополнительная подпапка

Старый relative path:

```text
Films/A.mkv
```

Новый:

```text
Moved/Films/A.mkv
```

Указать `Moved`.

Карточка должна сопоставиться с новым файлом, а DB path стать новым.

### Вариант C — файл изменен

Если relative path совпадает, но hash изменен, чужую карточку автоматически не присоединять. Отчет импорта должен отметить mismatch.

---

## 57. Безопасность

Проверить минимум:

- неавторизованный `media.php` не выдает видео;
- подстановка arbitrary absolute path не читает файл;
- `/uploads/foo.jpg` напрямую закрыт;
- `image.php` требует auth;
- POST/API без CSRF отклоняется;
- `../` в import subdir/ZIP entries отклоняется;
- выбор root вне `ALLOWED_MEDIA_ROOTS` отклоняется, если allowlist задан;
- config/worker files недоступны по HTTP при поддерживаемой конфигурации web server.

---

# ЧАСТЬ XVI. НЕЦЕЛИ

## 58. Что не требуется

На текущем этапе Solanace не обязан быть:

- публичным облачным сервисом;
- multi-tenant системой;
- полноценным RBAC;
- Plex/Jellyfin-совместимым streaming server;
- автоматическим movie metadata scraper;
- системой DRM;
- видеоредактором с timeline;
- transcoding farm;
- контейнеризованным приложением.

Архитектура должна оставаться понятной, локально устанавливаемой и ремонтопригодной без сложного build/deployment stack.

---

# ЧАСТЬ XVII. СТРУКТУРА КОДА

## 59. Рекомендуемая ответственность файлов

Текущая структура может сохраняться:

- `index.php` — основной UI;

- `api.php` — основной JSON API и файловые операции;
- `media.php` — авторизованная Range-выдача видео;
- `image.php` — авторизованная выдача attachments;

- `library_categories.php` — categories;
- `screenshot_worker*.php` — generation queue/worker;
- `file_tools_lib.php`, `file_tools_worker.php` — derivatives;

- `translation_lib.php`, `translation_worker.php`, `translation/providers/*` — translation;
- `video_merge_lib.php`, `video_merge_worker.php` — merge;
- `library_transfer_lib.php`, `utilities/library_transfer.php` — export/import;

- `assets/style.css` — appearance/responsive layout;
- `install.sql` — schema;

При дальнейшем росте допускается декомпозиция `api.php`/`app.js`, но публичное поведение должно соответствовать настоящему ТЗ.

## 60. Итоговое определение готовности

Разработчик может считать Solanace соответствующим ТЗ, если пользователь способен:

1. установить проект на Windows или Linux без Node/npm/Docker;
2. подключить существующую папку видео;
3. удобно перемещаться по дереву слева и файлам справа;
4. создавать и сохранять карточки, категории, заметки и фото;
5. искать по метаданным и транскриптам;
6. получать кадры и миниатюры;
7. просматривать видео;
8. делать аудио, фрагменты и MP4;
9. транскрибировать и переводить;
10. редактировать текст по таймкодам;
11. склеивать видео;
12. безопасно перемещать/удалять файлы;
13. экспортировать библиотеку и восстановить ее на новом инстансе, в том числе при переносе исходной структуры в дополнительную подпапку;
14. выполнять все это через единый минималистичный двуязычный интерфейс, не теряя связь между физическими файлами и пользовательскими метаданными.
