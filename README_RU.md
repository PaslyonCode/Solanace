# Solanace

**Solanace** — self-hosted веб-каталог и набор инструментов для локального видеоархива. Приложение индексирует выбранные папки сервера, показывает файловую структуру и миниатюры, хранит карточки и категории, создает кадры, умеет вырезать и склеивать видео, извлекать аудио, транскрибировать речь, переводить транскрипты и переносить библиотеку между инстансами.

Solanace рассчитан прежде всего на **внутреннее использование**: локальная сеть, VPN или доверенный reverse proxy. Это однопользовательское административное приложение, которому по назначению нужны права на чтение и, для файловых операций, запись в медиапапки сервера.

> Интерфейс двуязычный: русский / английский. Проект работает на Windows и Linux.

## Что умеет Solanace

### Библиотека и файловый менеджер

- подключение произвольной серверной папки как библиотеки;
- кэширование файловой структуры в MySQL/MariaDB, без полного рекурсивного сканирования при каждом открытии;
- дерево папок слева и содержимое выбранной папки справа;
- локальный поиск по дереву папок;
- кликабельные breadcrumbs для быстрого перехода к родительским каталогам;
- режимы отображения файлов **списком** и **миниатюрами**;
- сортировка по имени А–Я / Я–А и по длительности ↑ / ↓;
- создание папок, перемещение файлов и папок, drag-and-drop, физическое удаление;
- множественное выделение с групповыми операциями;
- закрепленные папки и закрепленные видео;
- отдельный поиск по библиотеке и фильтр по категориям;
- категории отдельны для каждой подключенной библиотеки;
- обновление кэша с определением добавленных, удаленных, измененных и перемещенных файлов;
- сохранение карточки при переименовании или перемещении файла благодаря стабильному `file_hash`;
- идентификация корня библиотеки через `.video_catalog_screenshots/library.id`, поэтому библиотека переживает смену пути или буквы диска.

### Карточка видео

Карточка открывается в широкоэкранном модальном окне с пропорциями колонок **1/4 — 2/4 — 1/4** и ограниченной максимальной шириной.

- имя исходного файла и путь;
- перелистывание соседних карточек текущей папки кнопками `‹ / ›`;
- горячие клавиши `Alt + ←` и `Alt + →`;
- выбранная миниатюра с запуском просмотра видео по клику;
- размер файла, длительность и дата добавления;
- пользовательский заголовок;
- категория;
- заметка;
- закрепление видео;
- создание новой категории прямо из карточки;
- 10 автоматически созданных кадров без скрывающего спойлера;
- выбор любого кадра как основной миниатюры;
- прикрепленные пользователем изображения;
- сведения о видео, созданных из фрагментов, и об исходнике фрагмента;
- сведения об исходных видео для результата склейки;
- удаление только карточки либо полное удаление видео с диска вместе с производными данными.

### FFmpeg и производные файлы

Единое окно **«Вырезка / Аудио / Транскрипт»** позволяет задать общий интервал и выполнить одну или несколько операций:

- вырезать видеофрагмент;
- получить MP3 или FLAC;
- создать транскрипт;
- одновременно получить нужную комбинацию результатов без дублирования аудио.

Поддерживаются:

- MP3: 64 / 96 / 192 кбит/с;
- FLAC;
- преобразование несовместимого с браузером видео в H.264/AAC MP4;
- сохранение производных файлов в служебной папке библиотеки;
- продвижение видеофрагмента в обычный видеофайл библиотеки;
- перенос связанного аудио, транскрипта и переводов к продвинутому фрагменту;
- коррекция таймкодов при превращении фрагмента в самостоятельное видео.

У фрагментов, аудио и транскриптов есть компактные меню действий по шестеренке. Название фрагмента открывает видео; название транскрипта открывает просмотр транскрипта.

### Автоматические кадры и миниатюры

- для каждого видео автоматически генерируются **10 кадров** по длительности;
- кадры хранятся рядом с библиотекой в `.video_catalog_screenshots/<file_hash>/`;
- генерация выполняется фоновым PHP CLI / FFmpeg worker'ом;
- отображается прогресс и текущий файл;
- worker можно остановить и продолжить;
- обработка восстанавливается после зависшего/оборванного состояния;
- плиточные миниатюры загружаются лениво через `IntersectionObserver`;
- назначенный пользователем кадр используется как основная миниатюра.

### Транскрибация

Текущий провайдер — **Groq / Whisper** через Python SDK.

Поддерживаются модели:

- `whisper-large-v3`;
- `whisper-large-v3-turbo`.

Язык задания:

- автоматически;
- русский;
- английский.

Solanace сохраняет:

- исходное аудио транскрипта;
- TXT;
- полный текст;
- сегменты с таймкодами;
- сведения о провайдере и модели.

Большие аудиофайлы разбиваются на части, а таймкоды при объединении корректируются.

### Просмотр и редактирование транскриптов

- сегменты показаны списком с таймкодами;
- клик по таймкоду запускает видео с соответствующей позиции;
- сегмент можно редактировать или удалить;
- можно вручную добавить новый сегмент в формате `[hh:mm:ss] текст`;
- оригинальный транскрипт и переводы доступны в одном окне;
- можно скачать TXT;
- прямо из окна просмотра доступна кнопка **«Перевести»**.

Текст транскриптов участвует в общем поиске по библиотеке.

### Переводы

Текущий провайдер — Groq. Поддерживаются модели:

- `openai/gpt-oss-20b`;
- `openai/gpt-oss-120b`.

Возможности:

- машинный перевод на русский и английский;
- несколько вариантов перевода одного транскрипта;
- импорт пользовательского перевода из TXT drag-and-drop или выбором файла;
- пользовательское имя варианта перевода;
- самостоятельная сегментация пользовательского перевода;
- редактирование, удаление и добавление сегментов;
- удаление отдельного варианта перевода;
- скачивание TXT в UTF-8 с BOM;
- сохранение выбранного варианта просмотра локально в браузере.

При машинном переводе используется пакетная обработка сегментов, контроль идентификаторов и автоматическое дробление пакета при лимитах API.

### Склейка видео

При выборе двух и более видео появляется действие **«Склеить»**.

В диалоге можно:

- менять порядок источников drag-and-drop;
- задавать имя результата;
- выбрать Auto / 1920×1080 / 1280×720;
- выбрать `fit/pad` либо `fill/crop` для несовпадающих пропорций;
- выбрать качество;
- позволить системе использовать быструю concat-склейку без перекодирования, если параметры источников совместимы;
- принудительно перекодировать в H.264/AAC.

Если у одного из источников нет аудио, при нормализации добавляется тишина. Процесс идет в фоне, а интерфейс показывает процент, обработанное/полное время, стадию и heartbeat.

Результат автоматически становится обычным видео библиотеки, получает карточку и набор из 10 кадров. В карточке сохраняется provenance — список исходных роликов в правильном порядке.

### Групповые инструменты

Меню **«Действия»** содержит:

- групповое добавление метаданных из XLSX/CSV;
- групповой просмотр метаданных;
- групповой просмотр кадров;
- экспорт библиотеки;
- импорт библиотеки;
- настройки;
- выход.

Импорт метаданных умеет сопоставлять файлы по имени/пути и назначать заголовок, заметку и категорию; отсутствующая категория создается автоматически.

### Экспорт и перенос библиотеки

**Экспорт библиотеки** создает ZIP в корне текущей медиапапки:

```text
solanace_export_YYYY-MM-DD_HH-MM-SS.zip
```

В архив входят:

- карточки, заметки и категории;
- назначения категорий;
- закрепления;
- выбранные миниатюры;
- кадры;
- производные аудио/видеофайлы;
- транскрипты, сегменты и переводы;
- связи склеек и продвинутых фрагментов;
- прикрепленные изображения;
- полезное содержимое `.video_catalog_screenshots`.

**Исходные видео не архивируются.** Также не экспортируются пароли приложения/БД, API-ключи Groq и настройки провайдеров.

Для переноса:

1. скопируйте исходные видео на новый сервер/диск;
2. скопируйте экспортный ZIP;
3. выберите новый корень в Solanace и загрузите его кэш;
4. откройте **Действия → Импорт библиотеки**;
5. при необходимости укажите **подпапку с перенесенными файлами** относительно нового корня;
6. выберите ZIP из корня библиотеки либо загрузите его через браузер;
7. запустите импорт.

Старые абсолютные пути и внутренние ID БД не переносятся. Видео сопоставляются по относительному пути, указанному префиксу подпапки и `file_hash`; новые записи создаются с ID нового инстанса. Структура исходных файлов не изменяется.

## Интерфейс

Основное окно рассчитано на широкоформатный монитор, но не растягивает отдельные поля на всю ширину. Поиск и фильтр категории находятся по центру и имеют ограниченную ширину.

Рабочая зона состоит из:

- дерева папок слева;
- файлов текущей папки справа;
- breadcrumbs над файлами;
- панели сортировки и переключения вида;
- отдельной области закрепленных видео;
- панели массовых операций, появляющейся только при выделении.

Дерево папок увеличивается вниз по мере раскрытия ветвей и не имеет отдельной вертикальной прокрутки. Поиск по папкам временно фильтрует дерево и раскрывает родительские ветви совпадений.

## Требования

- PHP **8.1+**; рекомендуются PHP 8.2/8.3;
- MySQL 8+ или современная MariaDB;
- Apache или Nginx;
- FFmpeg + ffprobe;
- PHP extensions:
  - `pdo_mysql`;
  - `mbstring`;
  - `fileinfo`;
  - `simplexml`;
  - `zip` / `ZipArchive` — обязательно для экспорта/импорта библиотеки;
  - `gd` желательно для уменьшенных плиточных миниатюр;
- Python — только для текущего Groq bridge.

Для Groq:

```bash
python -m pip install groq
```

## Установка с нуля

### 1. Скопируйте проект

Windows/Laragon:

```text
C:\laragon\www\solanace
```

Linux:

```text
/var/www/solanace
```

`uploads/` должен быть доступен PHP на запись. Медиапапки должны быть доступны на чтение, а для перемещения, удаления, FFmpeg и экспорта — на запись.

### 2. Создайте БД

По умолчанию `config.php` содержит:

```text
DB_HOST = 127.0.0.1
DB_NAME = solanace
DB_USER = admin
DB_PASS = admin
```

От имени администратора MySQL/MariaDB:

```bash
mysql -u root -p < database_bootstrap.sql
```

Затем:

```bash
mysql -u admin -p solanace < install.sql
```

Пароль пользователя БД по умолчанию: `admin`.

### 3. FFmpeg

Если `ffmpeg`, `ffprobe` и PHP CLI доступны в `PATH`, дополнительные настройки не нужны.

Можно также положить бинарники в:

```text
tools/ffmpeg/bin/
```

или указать пути в `config.php`:

```php
define('FFMPEG_PATH', '');
define('FFPROBE_PATH', '');
define('PHP_CLI_PATH', '');
```

Пустые значения означают автоматический поиск.

### 4. Первый вход

```text
login:    admin
password: admin
```

Пока стандартный пароль приложения и/или стандартный пароль БД не изменены, вверху главного экрана показывается предупреждающая плашка.

Пароль приложения меняется через **Действия → Настройки → Логин и пароль** и хранится через Argon2id.

## Настройки Groq

Откройте **Действия → Настройки** и задайте сервис, модель, API-ключ и при необходимости путь к Python.

Пример для Laragon:

```text
C:\laragon\bin\python\python-3.13\python.exe
```

Если настройки перевода Groq не содержат отдельный API-ключ/Python, используются соответствующие значения транскрибации.

## Безопасность и модель развертывания

Solanace следует размещать за VPN, LAN или доверенным reverse proxy. Не рекомендуется напрямую публиковать административный интерфейс в Интернет.

Реализовано:

- локальная авторизация;
- Argon2id;
- CSRF-токены;
- строгие PHP-сессии, HttpOnly, SameSite=Lax и Secure при HTTPS;
- CSP, X-Frame-Options, nosniff, Referrer-Policy и Permissions-Policy;
- проверка принадлежности путей выбранной библиотеке;
- prepared statements;
- защищенная выдача видео и прикрепленных картинок через авторизованные endpoints;
- запрет прямого HTTP-доступа к `uploads/`, worker/lib/SQL/Python-файлам в Apache;
- ограничение количества и размера загружаемых изображений;
- CLI-only workers;
- необязательный whitelist серверных медиакорней.

Для ограничения файловой системы:

```php
define('ALLOWED_MEDIA_ROOTS', [
    '/srv/media',
    '/mnt/archive',
]);
```

Windows:

```php
define('ALLOWED_MEDIA_ROOTS', [
    'D:\\Video',
    'E:\\Archive',
]);
```

Пустой массив сохраняет возможность выбирать любую папку, доступную системному пользователю PHP.

## Reverse proxy

Solanace по умолчанию не доверяет `X-Forwarded-*`. Если PHP доступен только через доверенный proxy, выставляющий `X-Forwarded-Proto`, можно включить:

```php
define('TRUST_PROXY_HEADERS', true);
```

## Apache и Nginx

В репозитории присутствуют `.htaccess`, закрывающие служебные файлы и прямой доступ к `uploads/`. Apache должен разрешать `AllowOverride`.

Nginx `.htaccess` не читает, поэтому аналогичные запреты необходимо настроить вручную. Пример:

```nginx
location ~* /(config|db|auth|library_identity|library_categories|.*_lib|.*_worker)\.php$ {
    deny all;
}
location ^~ /uploads/ {
    deny all;
}
location ~* \.(sql|py|pyc|log|ini|bak)$ {
    deny all;
}
```

## Где хранятся данные

Исходные видео остаются на месте.

В каждой библиотеке Solanace создает:

```text
<root>/.video_catalog_screenshots/
```

Внутри хранятся автоматические кадры, уменьшенные миниатюры, аудио, видеофрагменты, конвертированные версии и другие производные файлы.

MySQL/MariaDB хранит кэш структуры, карточки, категории, транскрипты, переводы, связи между файлами и состояния фоновых заданий.

В `uploads/` инстанса находятся прикрепленные пользователем фотографии; напрямую по HTTP каталог не выдается.

## Резервное копирование

Полный резервный набор:

1. база `solanace`;
2. исходные медиапапки;
3. `.video_catalog_screenshots` внутри библиотек;
4. `uploads/`.

Для переноса одной библиотеки между инстансами удобнее использовать встроенный экспорт/импорт.
