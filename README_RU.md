# Solanace

**Solanace** — локальный веб-каталог и набор инструментов для работы с видеоархивом. Приложение индексирует выбранные папки сервера, хранит карточки и категории, автоматически создает кадры, умеет вырезать и склеивать видео, извлекать аудио, транскрибировать и переводить текст.

Проект рассчитан прежде всего на **внутреннее использование** — локальная сеть, VPN или доступ через reverse proxy. Это не публичный многопользовательский облачный сервис.

## Основные возможности

- кэшируемая файловая структура с режимами «список» и «миниатюры»;
- карточки видео, заметки, категории и прикрепленные изображения;
- полнотекстовый поиск, включая транскрипты;
- 10 автоматических кадров на видео и выбор собственной миниатюры;
- закрепленные видео;
- массовые действия: перемещение, удаление, категория, склейка;
- FFmpeg: кадры, аудио, фрагменты, конвертация в MP4, склейка;
- транскрибация через провайдеры (сейчас Groq / Whisper);
- машинные и пользовательские переводы транскриптов;
- редактирование сегментов и переход по таймкодам;
- двуязычный интерфейс: русский / английский;
- простая локальная авторизация с Argon2id.

## Требования

- PHP **8.1+** (рекомендуется 8.2/8.3);
- MySQL 8+ или современная MariaDB;
- веб-сервер Apache или Nginx;
- FFmpeg + ffprobe;
- PHP-расширения: `pdo_mysql`, `mbstring`, `fileinfo`, `simplexml`;
- `gd` желательно для уменьшенных плиточных миниатюр;
- `zip` желательно для импорта XLSX (есть резервные варианты чтения);
- Python нужен только для текущего Groq-адаптера транскрибации/перевода.

Для Groq:

```bash
python -m pip install groq
```

## Установка с нуля

### 1. Скопируйте проект

Например, Windows/Laragon:

```text
C:\laragon\www\solanace
```

Linux/Apache:

```text
/var/www/solanace
```

Каталог `uploads/` должен быть доступен PHP на запись. Корневые папки медиатеки должны быть доступны PHP на чтение, а для перемещения/удаления/создания производных файлов — и на запись.

### 2. Создайте БД и пользователя

По умолчанию `config.php` настроен так:

```text
DB_HOST = 127.0.0.1
DB_NAME = solanace
DB_USER = admin
DB_PASS = admin
```

Для чистого локального MySQL/MariaDB можно от имени администратора БД выполнить:

```bash
mysql -u root -p < database_bootstrap.sql
```

Файл создаст базу `solanace` и пользователя БД `admin/admin`, имеющего права **только на базу Solanace**.

> `admin/admin` для базы используется только как удобное начальное значение. После установки рекомендуется изменить пароль пользователя MySQL/MariaDB и соответствующий `DB_PASS` в `config.php`.

### 3. Создайте таблицы

```bash
mysql -u admin -p solanace < install.sql
```

Пароль по умолчанию: `admin`.

То же самое можно сделать через phpMyAdmin: сначала выполнить `database_bootstrap.sql` под административным пользователем, затем `install.sql`.

### 4. FFmpeg

Если `ffmpeg`, `ffprobe` и PHP CLI есть в `PATH`, ничего настраивать не нужно.

Можно также положить FFmpeg сюда:

```text
tools/ffmpeg/bin/ffmpeg.exe
tools/ffmpeg/bin/ffprobe.exe
```

или явно указать абсолютные пути в `config.php`:

```php
define('FFMPEG_PATH', '');
define('FFPROBE_PATH', '');
define('PHP_CLI_PATH', '');
```

Пустые значения означают автоматический поиск. Это одинаково работает на Windows и Linux.

### 5. Первый вход

Откройте Solanace в браузере.

Логин приложения по умолчанию:

```text
admin
```

Пароль:

```text
admin
```

Пока используется пароль приложения `admin`, в верхней части интерфейса отображается предупреждающая плашка. Смените пароль через:

**Действия → Настройки → Логин и пароль**.

Пароли приложения хранятся через Argon2id. Для аварийной ручной смены хэша есть:

```text
tools/make_password_hash.php
tools/make_password_hash.py
```

## Настройка Groq

В интерфейсе откройте **Действия → Настройки** и укажите:

- сервис;
- модель;
- API-ключ;
- путь к `python` при необходимости.

Для Windows/Laragon путь может выглядеть так:

```text
C:\laragon\bin\python\python-3.13\python.exe
```

## Ограничение доступа к файловой системе

Авторизованный администратор Solanace по назначению может выбирать серверные папки, доступные пользователю PHP. Если сервер содержит другие важные каталоги, рекомендуется ограничить допустимые медиа-корни в `config.php`:

```php
define('ALLOWED_MEDIA_ROOTS', [
    '/srv/media',
    '/mnt/archive',
]);
```

Для Windows:

```php
define('ALLOWED_MEDIA_ROOTS', [
    'D:\\Video',
    'E:\\Archive',
]);
```

Пустой массив означает отсутствие дополнительного ограничения.

## Reverse proxy / HTTPS

По умолчанию Solanace не доверяет `X-Forwarded-*` заголовкам. Если приложение доступно **только** через доверенный reverse proxy, который корректно выставляет `X-Forwarded-Proto`, можно включить:

```php
define('TRUST_PROXY_HEADERS', true);
```

Это позволяет корректно ставить флаг `Secure` у сессионной cookie при HTTPS-терминации на прокси.

Не включайте параметр, если к PHP-серверу можно обращаться напрямую с недоверенной сети.

## Apache

В архив включены `.htaccess`, которые:

- запрещают листинг каталогов;
- закрывают прямой доступ к `config.php`, библиотечным/worker-файлам, SQL/Python-файлам;
- полностью закрывают прямой HTTP-доступ к `uploads/`;
- служебные папки `.video_catalog_screenshots` также получают защитный `.htaccess` автоматически.

Apache должен разрешать `AllowOverride` для каталога приложения.

## Nginx

Nginx игнорирует `.htaccess`. Рекомендуется явно закрыть служебные файлы, например:

```nginx
location ~* /(config|db|auth|library_identity|library_categories|.*_lib|.*_worker)\.php$ {
    deny all;
}
location ^~ /uploads/ {
    deny all;
}
location ~* \.(sql|py|pyc|md|log|ini|bak)$ {
    deny all;
}
```

При размещении Solanace в подпапке скорректируйте `location` под свой URL.

## Безопасность

Перед подготовкой этого install-архива код был дополнительно просмотрен на очевидные проблемы внутреннего веб-приложения. В частности:

- удален диагностический `wrtest.php`, позволявший писать тестовый файл без авторизации;
- `media.php` больше не может читать произвольный путь, переданный в base64 — выдаются только видео, зарегистрированные в `library_files`;
- карточку нельзя создать по произвольному пути вне кэша;
- прикрепленные изображения больше не выдаются напрямую из `uploads/`; используется авторизованный `image.php`;
- добавлена CSRF-защита всех изменяющих JSON-запросов;
- добавлены `CSP`, `X-Frame-Options`, `nosniff`, `Referrer-Policy` и `Permissions-Policy`;
- сессия использует strict mode, HttpOnly, SameSite=Lax и Secure при HTTPS;
- добавлены ограничения размера и количества прикрепляемых изображений;
- пути файловых операций проверяются на принадлежность выбранной корневой библиотеке;
- SQL-запросы с пользовательскими значениями выполняются через prepared statements;
- worker-скрипты допускают запуск через CLI, но не как обычные веб-endpoint'ы;
- пользователь MySQL по предлагаемой установке получает права только на БД `solanace`.

Solanace все равно следует размещать за VPN / reverse proxy и не публиковать напрямую в Интернет без дополнительного внешнего слоя защиты.

## Хранение данных

Основные видео остаются в выбранных пользователем папках. Служебные данные рядом с видео сохраняются в:

```text
<library root>/.video_catalog_screenshots/
```

Там находятся кадры, производные аудиофайлы, фрагменты и другие результаты обработки.

Карточки, категории, транскрипты, переводы и состояние задач хранятся в MySQL/MariaDB.

## Резервное копирование

Для полноценного бэкапа сохраняйте одновременно:

1. базу `solanace`;
2. исходные медиапапки;
3. `.video_catalog_screenshots` внутри них;
4. каталог `uploads/` приложения.
